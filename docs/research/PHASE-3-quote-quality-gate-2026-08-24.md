# Phase 3 研究報告:報價質素閘門(Quote Quality Gate)

**日期:** 2026-08-24
**狀態:** ✅ 已實作(2026-08-24):閘門模組 + gated 影子雙生線 + API/UI 全部落地,測試全綠;replay 待部署後喺 VM 執行 — 詳見 `PHASE-3-results-2026-08-24.md`。本設計文檔保留做設計依據:係四個 Phase 入面最直接對治已知死因嘅一個
**目的:** corner-loo-v1 嘅直接死因唔係「角球」而係「將錯價當價值」。無論將來邊個模型出推薦,都需要一個獨立於模型嘅報價質素閘門。呢個 Phase 係所有未來推薦嘅安全帶。

## 1. 死因分析(嚟自 validity 報告嘅硬證據)

| 分組 | 推薦數 | 實際命中率 | ROI |
|---|---:|---:|---:|
| 角球 `over` | 100 | 8.0% | -75.4% |
| 賠率 10 倍以上 | 34 | **0%** | **-100%** |
| edge 20% 以上 | 20 | **0%** | **-100%** |
| edge 3–5% | 33 | 33.3% | -6.9% |

兩個鐵一般嘅規律:

1. **越高賠率越係陷阱** — 10 倍以上 34 注全軍覆沒。呢啲唔係「被低估嘅冷門」,係莊家報價錯誤(過期盤、錯盤、流動性為零嘅掛單價)。
2. **edge 越大越差** — 個引擎嘅核心假設(「偏離共識 = 機會」)喺極端區間完全反轉。真實情況係:偏離共識好多 = 嗰個莊家錯,唔係市場錯。

涉案莊家:Betfair(exchange 掛單價可以係無成交嘅離譜價)、Superbet 等被點名。

## 2. 設計原則

閘門分兩邊,缺一不可:

### 2.1 共識側:邊啲莊家有資格定義「真相」

- 現行 `consensus-v1`/LOO 對所有莊家一視同仁 — 軟莊家嘅錯價會污染共識本身。
- `market-sharp.mjs` 嘅 `BOOKMAKER_WEIGHTS` 已經係現成基礎(Pinnacle 1.0、Betfair 0.9、HKJC 0.1)。
- **閘門版:共識只用可信名單(allowlist)**,而唔係加權咁簡單 — 出名慢/錯價多嘅來源直接唔入共識。

### 2.2 買入側:邊啲報價有資格成為推薦

| 檢查 | 規則 | 針對嘅死因 |
|---|---|---|
| 賠率上限 | 每玩法設 cap(例如角球 >6.0、主客和 >8.0 唔出推薦) | 10 倍以上全滅 |
| Edge 上限 | 同 3% 下限對稱,設上限(例如 >15% 視為錯價唔係價值) | edge 20%+ 全滅 |
| 偏離檢查 | 報價隱含概率偏離 sharp 共識超過指定 band → 當錯價剔除 | 「偏離 = 機會」假設反轉 |
| 盤口一致性 | 同一莊家唔同盤口嘅價錢要單調(例如 -0.5 主勝價唔可以平過 -1) | 錯盤/過期盤 |
| 新鮮度相對檢查 | 報價 `observedAt` 明顯舊過同場其他莊家 → 剔除 | 過期報價 |

## 3. 核心兩難(要誠實面對)

edge 嘅來源本來就係軟莊家偏離市場。**閂得太緊 = 冇推薦;太鬆 = 冇保護。**

處理方法:

1. **共識側可以閂得緊**(定真相要嚴),**買入側閂喺極端位**(只擋明顯錯價,唔擋合理偏離)。
2. 所有參數(賠率 cap、edge 上限、偏離 band)唔靠估 — 用下面 §4 嘅 replay + 影子 A/B 決定。
3. 閘門係**獨立模組**,套喺推薦出街前最後一步,任何策略(unified/shadow/將來嘅 blend/角球模型)都行同一道閘。

## 4. 驗證方法

### 4.1 Replay 驗證(可以即刻做)

用 validity 報告嘅 164 個角球推薦做測試集(佢哋嘅結局全部已知):

- 閘門應該擋到:10 倍以上嗰 34 注(全滅嗰批)、edge 20%+ 嗰 20 注
- 閘門應該保留:合理區間嘅推薦
- 報告「擋咗幾多 % 嘅虧損 vs 擋咗幾多 % 嘅盈利」— 理想係大比例擋虧損、細比例誤擋

呢個 replay 直接出參數表,唔使等未來數據。

### 4.2 影子 A/B(向前驗證)

同一條影子線出兩個版本:有閘門 vs 冇閘門(新 `strategyVersion` 後綴,例如 `dc-blend-v1-gated`),行幾個月比較。呢個係預先登記嘅 A/B,唔係事後揀贏家。

## 5. 實作計劃

| 步驟 | 內容 | 涉及檔案 |
|---|---|---|
